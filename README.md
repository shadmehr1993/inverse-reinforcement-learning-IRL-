## Overview

This repository provides a modular implementation of an **Inverse Reinforcement Learning (IRL) agent** for supervisory HVAC control in district energy systems.

Unlike standard Reinforcement Learning — where the reward function is manually designed — IRL **automatically infers the reward function** that best explains an expert controller's behavior. In this project, expert demonstrations are generated by a **Rule-Based Controller (RBC)**, and the IRL framework recovers the implicit reward structure encoding trade-offs between:

- ⚡ Energy consumption
- 💶 Operational cost
- 🌡️ Thermal comfort
- ⚙️ System stability

Once the reward function is recovered, it is used to train a control policy that **reproduces or improves upon** the expert behavior — without requiring manual reward engineering.

> ⚠️ **Note:** This repository provides a **partial implementation** of the IRL agent used in the study. The full experimental framework, including the complete co-simulation environment and additional control strategies, is part of the associated research publication. The shared code is intended for **educational purposes and reproducibility of the IRL methodology**.

## IRL vs. Other Approaches

| Approach | Reward Function | Learning Signal | This Repo |
|---|---|---|---|
| Rule-Based Control (RBC) | Hand-crafted rules | None | Expert source |
| Behavioral Cloning (BC) | Not learned | Supervised (actions) | [BC repo](https://github.com/shadmehr1993/Behavioral-Cloning) |
| **IRL** (this repo) | **Learned from demos** | **Inferred from behavior** | ✅ |
| Deep RL / TL | Manual design | Environment reward | [TL repo](https://github.com/shadmehr1993/TL-hpc-cooling) |

The key advantage of IRL over Behavioral Cloning is that IRL recovers the **underlying objectives** of the expert, not just the surface-level actions — making it more robust to unseen states.

## System Description

The IRL agent controls a **district-scale HVAC system** composed of heat pumps, thermal storage, and PV generation. The controller operates supervisory setpoints at each timestep.

```
Expert RBC Demonstrations
        │
        ▼
┌─────────────────────┐
│   IRL Training      │  ←── State-Action pairs
│   (Reward Learning) │
└─────────┬───────────┘
          │  Learned Reward Function R(s, a)
          ▼
┌─────────────────────┐
│   Policy            │  ←── Optimized with learned reward
│   Optimization      │
└─────────┬───────────┘
          │  Control Policy π(s)
          ▼
┌─────────────────────┐
│   HVAC Environment  │  ←── SWT setpoint, flow rate, storage
└─────────────────────┘
```

### Input State Vector

| Variable | Description |
|---|---|
| Supply Water Temperature (SWT) | Current supply temperature from heat pump |
| Return Water Temperature (RWT) | Return temperature from building loop |
| Outdoor Temperature | Ambient air temperature |
| Cooling Demand | Building thermal load requirement |
| Electricity Price Signal | Time-of-use tariff for cost-aware control |
| PV Generation | Available photovoltaic power output |

### Output Action Vector

| Variable | Description |
|---|---|
| SWT Setpoint | Target supply water temperature |
| Pump Mass Flow Rate | Hydraulic flow rate command |
| Storage Operation | Thermal storage charge / discharge command |

## Pipeline

The workflow follows four sequential steps:

```
Step 1              Step 2                Step 3            Step 4
──────────          ──────────────        ──────────        ──────────────
Run RBC        →    Learn Reward     →    Optimize     →    Deploy &
Collect             Function via          Policy with        Evaluate
Expert Data         IRL Training          Learned R(s,a)     IRL Agent
```

### Step 1 — Collect Expert Demonstrations
```bash
python collect_IRL_data/run_collection.py
```
Runs the RBC on the environment and records state–action–trajectory pairs for IRL training.

### Step 2 — Train the IRL Reward Network
```bash
python IRL_train/train.py
```
Learns a reward function `R(s, a)` that explains the expert's behavior using Maximum Entropy IRL or a similar framework. Saves the trained reward model to `models/`.

### Step 3 — Run the IRL Controller
```bash
python IRL_controller/run.py
```
Loads the trained reward and policy models, applies the IRL agent in the simulation environment.

## Methodology

### Why Inverse Reinforcement Learning?

In many real-world control problems, designing a reward function that captures all relevant objectives is difficult. IRL addresses this by **recovering the reward function directly from expert behavior**:

```
Expert Demonstrations  →  IRL  →  Reward Function  →  RL  →  Optimal Policy
```

**Advantages over Behavioral Cloning:**
- Recovers **why** the expert acts, not just **what** the expert does
- More robust generalization to unseen states
- Recovered reward can be reused across different environments
- Provides interpretable insight into expert objectives

### Maximum Entropy IRL

The reward function is learned by maximizing the likelihood of the observed expert trajectories under a maximum entropy distribution:

```
R*(s, a) = argmax_R  E_expert[R(s,a)] - log Z(R)
```

where `Z(R)` is the partition function ensuring the policy distribution has maximum entropy — preventing reward over-fitting to specific trajectories.
